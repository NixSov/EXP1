# Подготовка обновления, 10 ноября 2026

Ветка `codex/chat-reliability-attachments`.

## Сделано

- Проверка владельца peer перед выходом и удалением сигналов.
- Новые сообщения выбираются от курсора вперёд; прочитанный курсор ограничен выданной страницей.
- Запросы записи не повторяются автоматически при неоднозначном сбое. Неисправный маршрут исключается для следующего действия. Полной идемпотентности ручных повторов пока нет.
- Убрана выдача админских прав по отображаемому имени. Уже назначенные права нужно проверить вручную по UUID: автоматического отзыва нет.
- Картинки и файлы до 2 МБ в обоих чатах, просмотр изображений по нажатию и сохранение файла. Байты хранятся закрыто в Postgres, выдаются через RPC после проверки членства. Это начальный вариант для небольших вложений; трафик и размер базы расходуют квоты Supabase. Для крупных файлов потребуется отдельное объектное хранилище.
- Временные вложения каскадно удаляются вместе с сообщениями после выхода последнего участника. Отправка файла и выход сериализованы блокировкой комнаты. Постоянные чаты сохраняются.
- Отдельный аудиоканал демонстрации сохраняет работу микрофона. Windows-backend закреплён на конкретном commit flutter-webrtc: системный захват исключает процесс приложения. Для окна самого приложения аудио отключается. В браузере звук разрешён только для другой вкладки Chrome/Edge с проверкой capture handle; системный микс и вкладка Shronshiki отклоняются. Видеорендерер заглушён, чтобы не проигрывать второй раз аудио, уже выводимое отдельным рендерером.
- Проверки Flutter, SQL и сборок Windows/Android добавлены в отдельный workflow для PR. Он не публикует обновления пользователям.

## Развёртывание

1. Сделать резервную копию базы и проверить текущих администраторов `app_admins` по UUID.
2. Применить по порядку `20261110010000_attachments.sql`, затем `20261110020000_chat_reliability.sql` в Supabase SQL Editor. Старую изменённую миграцию chats повторно запускать не требуется.
3. Протестировать двумя аккаунтами и устройствами: обе разновидности чатов, сохранение/скачивание файла, выход последнего участника, микрофон одновременно с демонстрацией звука, показ окна Shronshiki, поздний вход зрителя и восстановление соединения.
4. Только после успешной проверки сливать в основную ветку: существующий workflow выпустит подписанное обновление с прежним ключом. Артефакт Android из PR подписан тестовым ключом и не заменяет установленное приложение.

## Проверки и ограничения

Flutter/Dart восстановлены: 3.47.8 / 3.13.7. Локальные unit/widget-тесты, анализатор и веб-сборка проверяются перед публикацией ветки. SQL проверяется настоящим PostgreSQL-движком PGlite с изолированными тестовыми auth-функциями; это не доступ к действующей базе. Живые сетевые тесты требуют отдельной конфигурации и по умолчанию пропускаются.

В локальной системе отсутствует Android SDK, установка Visual Studio неполная. Полноценная аппаратная проверка звука и эха не заменяется unit-тестами и пока не выполнена. Действующая база и установленное приложение не изменялись.

## Произвольные коды комнат

Технически кириллица, другие алфавиты и знаки поддерживаются PostgreSQL и Dart. Сейчас ограничения действуют в SQL CHECK, admin_pick_code, клиентском normalizeCode и парсинге ссылок. Их следует менять совместно: хранить каноническую форму NFC, кодировать сегмент ссылки через Uri.encodeComponent, явно определить регистр и ограничить длину. Управляющие, невидимые и двунаправленные управляющие символы лучше запрещать. Старые коды нужно сохранить совместимыми. В этом обновлении формат кодов не меняется: запрос был на оценку возможности, а не смену формата.
