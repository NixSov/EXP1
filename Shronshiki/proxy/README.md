# Посредник Shronshiki → Supabase (Vercel или Deno Deploy)

Нужен, когда у провайдера `*.supabase.co` недоступен или очень медленный
(Supabase работает через Cloudflare, а соединения с ним часть российских
операторов режет). Адреса `*.vercel.app` и Deno Deploy из России доступны —
проверено «Проверкой площадок» в приложении.

Общий код — `proxy.ts`; `api/proxy.ts` (с перенаправлением из `vercel.json`) запускает его на Vercel, `main.ts` —
на Deno Deploy. Приложение принимает несколько посредников через запятую и само
выбирает тот, что отвечает быстрее.

Пересылает только `/auth/v1/*` и `/rest/v1/*` в один проект Supabase.
`GET /health` — проверка доступности. Ключей не хранит.

## Развёртывание на Vercel (основной)

1. vercel.com → **Sign Up** → **Continue with GitHub** (тариф Hobby, бесплатно, без карты).
2. **Add New… → Project** → импортировать репозиторий `shronshiki-proxy`.
3. Framework Preset: **Other**; в **Environment Variables** добавить
   `SUPABASE_URL` = `https://<проект>.supabase.co` → **Deploy**.
4. Открыть `https://<проект>.vercel.app/api/health` — должно быть `ok`.
5. Адрес посредника: `https://<проект>.vercel.app/api` (с `/api` на конце).

## Развёртывание на Google Apps Script (для сетей, где закрыт и Vercel)

Google из России открывается стабильно. Apps Script не передаёт скрипту заголовки
запроса, поэтому приложение само «упаковывает» запрос в JSON (адрес вида
`…/macros/s/…/exec` оно узнаёт и делает это автоматически). Код — `apps_script_proxy.gs`.

1. script.google.com → **Новый проект** → вставить `apps_script_proxy.gs` вместо всего текста.
2. **Начать развертывание → Новое развертывание** → тип **Веб-приложение**;
   «Запуск от имени»: **Я**, «У кого есть доступ»: **Все** → **Развернуть** → разрешить доступ.
3. Адрес веб-приложения (`https://script.google.com/macros/s/…/exec`) добавить в список
   посредников. Проверка: открыть сам адрес (без `/health` — с добавкой к пути Google
   просит войти) — должно быть `{"s":200,…,"b":"ok"}`. Если просит войти и без добавки —
   в редакторе выполните `doGet` (▷ Выполнить) и выдайте разрешения.

Лимит Google для обычного аккаунта — 20 000 внешних запросов в сутки (около 13 часов
разговора вдвоём); запросы через Apps Script медленнее (0,5–1 с).

## Развёртывание на Deno Deploy (запасной)

Deno Deploy пока не запускает код из подпапки, поэтому `main.ts` кладётся
в отдельный репозиторий (в его корень).

1. console.deno.com → войти через GitHub → создать организацию.
2. **+ New App** → выбрать репозиторий с `main.ts` → **Create App**.
3. Настройки приложения → **Environment Variables** → **+ Add variable**:
   `SUPABASE_URL` = `https://<проект>.supabase.co`, контекст *Production* → **Save**.
4. Открыть адрес приложения + `/health` — должно быть `ok`.
5. Адрес приложения вписать в Shronshiki: **Настройки → Supabase и TURN → Посредник**
   (или `PROXY_URL` в `config/app_config.json` при сборке). Несколько посредников —
   через запятую.

## Локальная проверка

```bash
SUPABASE_URL=https://<проект>.supabase.co deno run --allow-net --allow-env main.ts
curl http://localhost:8000/health
```

## Лимиты бесплатного тарифа Deno

У Deno Deploy Free есть месячные лимиты: 1 млн запросов, 20 ГБ трафика, 10 часов
процессора и 150 ГБ·ч памяти (около 200 часов, пока посредник запущен). Посредник
запущен, пока к нему идут запросы, и выключается через 20–30 секунд тишины.
Поэтому приложение опрашивает сервер редко, когда все уже соединились (раз в 5 с),
а упоминания проверяет раз в 2 минуты. Расход виден в console.deno.com → Usage.
При превышении Deno приостанавливает приложение (`USAGE_EXCEEDED`).
На деле у новой организации лимиты оказались в сто раз меньше (10 тыс. запросов,
1,5 ГБ·ч памяти), поэтому основной посредник — Vercel.
